# Wire Protocol Definitions (`proto/`)

This directory contains Protocol Buffer (Protobuf v3) definitions defining the binary wire format for `chatapp` message envelopes.

---

## Specification: `envelope.proto`

All message units transferred over MQTT (`out/#` and `u/{recipient}/inbox`) conform to the `Envelope` schema:

```protobuf
syntax = "proto3";

package chatapp;

enum EnvelopeType {
  ENVELOPE_TYPE_UNSPECIFIED = 0;
  MESSAGE = 1;                     // Encrypted message payload
  RECEIPT = 2;                     // Delivery or read acknowledgment
  TYPING = 3;                      // Ephemeral typing indicator
  CALL_SIGNAL = 4;                 // WebRTC VoIP/video call signaling
  SENDER_KEY_DISTRIBUTION = 5;     // Group messaging sender key distribution
  EDIT = 6;                        // Message modification (within 15 mins)
  DELETE = 7;                      // Message deletion (me / everyone)
  REACTION = 8;                    // Emoji reaction
}

message Envelope {
  uint32 version = 1;              // Wire version (current: 1)
  string id = 2;                   // ULID unique identifier
  string sender_user = 3;          // Sender ULID
  uint32 sender_device = 4;        // Sender device ID (default: 1)
  string recipient_user = 5;       // Recipient ULID
  uint32 recipient_device = 6;     // Recipient device ID (default: 1)
  EnvelopeType type = 7;           // Envelope payload category
  int64 timestamp = 8;             // Milliseconds unix epoch
  bytes ciphertext = 9;            // Signal Protocol encrypted payload
}
```

---

## Field Breakdown

| Field | Type | Description |
|---|---|---|
| `version` | `uint32` | Schema version to ensure backward compatibility across client updates. |
| `id` | `string` | Universally Unique Lexicographically Sortable Identifier (ULID) generated by sender. |
| `sender_user` | `string` | User ID of the sender. Must match the client's authenticated JWT subject. |
| `sender_device` | `uint32` | Device index of the sender (e.g. `1` for primary device). |
| `recipient_user` | `string` | Destination user ID. |
| `recipient_device` | `uint32` | Destination device ID. |
| `type` | `EnvelopeType` | Categorizes the inner payload for fast routing without inspecting ciphertext. |
| `timestamp` | `int64` | Client-side creation timestamp in milliseconds unix epoch. |
| `ciphertext` | `bytes` | Opaque Signal Protocol ciphertext. Contains the encrypted JSON payload. |

---

## Envelope Lifecycle & Privacy

- **Zero-Knowledge Transport**: Intermediate brokers (`mosquitto`), routers (`router`), and databases (`postgres`) only inspect routing header fields (`sender_user`, `recipient_user`, `type`).
- **Encrypted Payload**: `ciphertext` cannot be decrypted or inspected by any server component—only the destination device holding the corresponding Double Ratchet private keys can decrypt the content.

## Compilation Guidelines

### Python
To compile Python protobuf stubs:
```bash
python -m grpc_tools.protoc -I. --python_out=../shared/py/src/chatapp_shared/proto envelope.proto
```

### TypeScript
To compile TypeScript types using `ts-proto`:
```bash
npx protoc --plugin=./node_modules/.bin/protoc-gen-ts_proto --ts_proto_out=../client/src/proto --proto_path=. envelope.proto
```
